# 飞书接入

## 接入方式

飞书使用 `lark-channel-sdk` 的 WebSocket 长连接，支持私聊、群聊提及、话题线程及图片、文件接收。最终文本通过适配器发送，开启 streaming 时使用 CardKit 展示。应用不需要公网事件回调地址。

连接由统一 Channel Runtime 持有。消息进入共享 PostgreSQL 队列，Agent Worker 执行后提交 Outbox，再由 Channel Runtime 投递；完整步骤见[运行时序](运行时序.md)。

## 配置

1. 创建企业自建应用，启用机器人和长连接消息事件订阅，取得 App ID 与 App Secret。
2. 根据所用 SDK 功能配置消息接收、机器人发送和 CardKit 写入权限。仓库集成使用消息与卡片接口，CardKit 需 `cardkit:card:write`。
3. 发布并安装应用。在 `/tenant` 的 IM 接入中选择飞书，填写 Agent、App ID、只写 App Secret，启用 Binding。
4. 检查 Runtime 连接状态，先用私聊文本验证，再测试群聊、线程和媒体。

权限名称和应用安装状态以实际租户控制台为准。表单来自 Adapter Schema，若字段缺失先检查迁移和部署版本，不把密钥补进代码。App Secret 由租户 SecretStore 加密保存，页面与查询接口不回显。

## 提示、会话与回复

`account_config.thinking_message` 控制可见的处理中提示，默认“正在思考...”，空字符串关闭。提示在入队成功后尽力发送，与 SDK 的底层确认分开；失败不丢弃已入队任务。

群聊默认要求提及机器人，话题使用 thread ID 参与 Conversation 映射。数据库保留租户、Binding 与外部会话范围，不能仅使用消息文字或用户显示名判断会话。

Worker 先保存最终结果和 Outbox，再由飞书 Adapter 使用 CardKit 等接口展示。分段卡片回复不代表模型首 token 已经实时送达用户。CardKit 权限缺失需要修正应用权限，不能通过放宽平台授权解决。

媒体累计默认不超过 50 MiB，下载后写租户 Artifact。是否能够解析或理解具体内容取决于文件格式和模型配置，不因 SDK 能接收就默认支持。

## 投递失败

明确失败按策略有限重试；回执不确定或过期 PROCESSING 转 UNKNOWN，不自动重发。同回复流的后续回复会等待核对，其他会话仍可继续。

管理员核实已收到后使用“确认已送达”，核实未收到后再决定“重新投递”。接口权限、理由和审计规则与企业微信一致，见[故障运维与恢复](故障运维与恢复.md)。

## 验收

分别测试私聊、群聊、话题、文件与图片，再验证停用/启用 Binding。重复消息应以外部 message ID 为准；相同文字的新消息不能被错误去重。实际人工记录见[测试结果](测试结果.md)，当前没有飞书线上强制断连的自动化验收结论。
