# 飞书接入

核对日期：2026-10-06，代码基线 `89d213d`。本页说明当前项目的接入方式、配置字段和排查步骤。本次为文档核对，没有重新连接真实飞书账号或调用模型。

## 接入方式与前提

项目使用 `lark-channel-sdk` 的 WebSocket 长连接，连接由独立的 Channel Runtime 持有。飞书事件进入 PostgreSQL 队列，Worker 执行模型和工具，结果提交到 Outbox 后再由 Channel Runtime 回复。普通 Worker 不持有飞书连接，消息不必经过 Gateway HTTP。

需要准备：

- 飞书企业自建应用，开启机器人能力，取得 App ID 和 App Secret。
- 飞书侧可用的消息事件权限、应用可用范围和发布版本。
- 平台侧启用的租户、可执行的 Agent、可用模型策略，以及启用的飞书 Adapter 和 Binding。Binding 是“这个应用绑定到哪个租户 Agent”的配置记录。
- Channel Runtime 能访问飞书长连接和 HTTPS API，Worker 能访问模型服务，媒体处理能访问对象存储。

不需要公网事件回调地址，也不需要把本机 8000 端口开放给飞书。默认租户控制台为 `http://127.0.0.1:8000/tenant`；修改过监听端口时使用实际地址。`start.sh` 会启动 Gateway、Worker Supervisor 和 Channel Runtime，单独启动 API 并不足以收发机器人消息。

## 飞书侧配置顺序

1. 在飞书开放平台创建企业自建应用，启用机器人能力，保存 App ID 和 App Secret。
2. 在权限管理中，根据实际使用功能申请机器人发送消息、接收单聊消息、接收群聊提及，以及图片/文件资源访问权限。使用 CardKit 流式展示时，还需检查 `cardkit:card:write` 等所调用卡片接口的权限。
3. 在“事件与回调”选择长连接接收事件，订阅接收消息事件 `im.message.receive_v1`。如果页面要求先建立长连接，可先完成下文的平台 Binding 配置，看到认证成功后再保存订阅。
4. 发布应用版本，完成所在企业需要的审批或启用步骤，确认测试用户处于应用可用范围。权限改动后也要确认新版本已经生效。
5. 先在私聊里测试，再把机器人加入测试群并提及它。

权限应按飞书接口对应的要求申请，不需要为测试本项目直接开放“读取所有群消息”。当前代码固定设置 `require_mention=True`；给应用更多权限不会自动让项目开始处理所有未提及机器人的群消息。

飞书后台入口和权限展示以实际控制台为准。官方参考：[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[事件订阅方式](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case)、[创建卡片实体](https://open.feishu.cn/document/cardkit-v1/card/create)。这些页面动态加载；本文的项目行为另外按本仓库代码核对。

## 在项目中配置

进入 `/tenant` 的“IM 接入”，选择飞书、选择 Agent，填写 App ID 和 App Secret。保存后配置会由 Channel Runtime 同步；默认轮询间隔为 5 秒，可由 `TRPC_SERVICE_CHANNEL_RECONCILE_INTERVAL_SECONDS` 调整。5 秒是同步间隔，不是网络认证必定完成的时限。

| 字段 | 位置 | 用途与实际行为 |
| --- | --- | --- |
| `app_id` | `account_config` | 必填，飞书应用 ID |
| `app_secret` | `secret_values` | 创建时提供的只写密钥，由租户 SecretStore 加密保存 |
| `thinking_message` | `account_config` | 可选，最长 200 字符；设为 `""` 关闭处理中提示 |
| `streaming` | `capabilities` | 只有布尔值 `true` 才走 CardKit 分段展示；省略或 false 走普通发送 |
| `max_inbound_media_bytes` | `capabilities` | 单条消息中下载媒体的累计字节上限，缺省为 52,428,800 字节，即 50 MiB；需为正整数 |

表单 Schema 提供的提示语默认值是“正在思考，请稍候…”，适配器在字段完全缺省时的兜底值是“正在思考...”。两者有区别，最清楚的做法是显式填写想展示的内容。提示通过 SDK 的普通 Markdown 发送路径发送，并不因为它是“处理中提示”就必须走 CardKit。

当前租户表单提交账号字段和密钥，**没有专门的 streaming 或媒体上限开关**。需要调整这两项时使用 Binding API。渠道目录 `capabilities` 描述 Adapter 能力，不会自动复制到新 Binding。

### API 配置示例

以下是请求体示例，UUID 和凭据均需替换。默认 API 前缀 `/api/v1`；请求需通过本项目管理认证，Cookie 登录还需按控制台机制携带 CSRF 信息，详见 [管理员模块设计](管理员模块设计.md)。

`POST /api/v1/tenants/{tenant_id}/channel-bindings`

```json
{
  "agent_app_id": "00000000-0000-0000-0000-000000000001",
  "channel_type": "feishu",
  "account_config": {
    "app_id": "替换为应用AppID",
    "thinking_message": "已收到，正在处理。"
  },
  "secret_values": {
    "app_secret": "替换为应用AppSecret"
  },
  "capabilities": {
    "streaming": false,
    "max_inbound_media_bytes": 52428800
  }
}
```

先以普通发送验证链路，确认卡片权限可用后，可用 `PATCH /api/v1/tenants/{tenant_id}/channel-bindings/{binding_id}` 更新：

```json
{
  "capabilities": {
    "streaming": true,
    "max_inbound_media_bytes": 52428800
  }
}
```

JSON 字段是整块替换，不是递归合并；若原 capabilities 还有其他设置，应一并保留。更新 account_config 时也要带上 app_id。通常无需提交 `external_account_hash`，服务会从应用身份生成。

查询只返回已配置的 `secret_fields` 名称，不回显 App Secret 或其内部存储引用。轮换密钥使用 PATCH 的 `secret_values.app_secret`；不改密钥时省略 `secret_values`，不要发送空字符串，也不要把星号占位符当新密钥。`secret_values` 与 `secret_ref_map` 不能同时提交。保留 `.secrets/tenant_secret_master_key`，否则已有租户密文可能无法解密。

## 连接、会话与回复的实际行为

配置记录显示 active 只代表启用，不证明应用已认证。使用 `start.sh` 时检查 `.run/channel-runtime.log` 中的 `Feishu binding authenticated`，并按 binding_id 关联；Runtime 进程心跳也不等于每个 Binding 都已连接。

群聊要求提及机器人。存在 thread_id 时按线程映射会话，否则区分私聊和群聊，再加上租户与 Binding 范围。会话身份不由消息文字或显示名决定。

处理中提示在任务可靠入队后尽力发送，提示失败不撤销任务。媒体先下载、存储再入队，因此大文件会拉长首次提示时间；50 MiB 是本项目下载后的累计校验，不是飞书全部接口的统一限制，也不意味着所有格式都能解析。

最终回答由 Worker 汇总并提交 Outbox 后才进入飞书发送。开启 streaming 时适配器把这份完整结果交给 CardKit 分段展示，**不是模型每生成一个 token 就直接推送给飞书**。适配器缺省普通发送返回 Markdown 内容，SDK 会按其消息能力处理；不能把“关闭 streaming”理解成从此所有卡片相关权限都无需检查。

资源接收覆盖图片、文件以及 SDK 提供的音视频等资源描述，具体内容理解取决于模型和解析器。支持接收一个文件不意味着模型能阅读任意文件，和知识库上传格式、大小限制也不是同一套规则。

## 停用、轮换与彻底删除

- **临时断开：** 在 IM 接入列表停用 Binding。同步后断开长连接，配置和历史记录保留。重新启用前会检查 Agent 是否可执行。
- **轮换 Secret：** 更新同一个 Binding 的密钥。Binding 更新时间变化会使 Runtime 重建连接；等待认证日志后再验收。
- **更换 App ID：** 建议建立新的 Binding，先停用旧绑定，避免混淆账号身份和历史会话。新的 Binding 会进入新的会话映射范围。
- **彻底删除：** 先处理未完成任务和投递，再停用，打开删除预览，确认影响范围并按预览要求输入名称。接入专属记录和不再被其他接入引用的租户密钥会被清理；不会删除飞书开放平台里的应用。

旧的 `DELETE /api/v1/tenants/{tenant_id}/channel-bindings/{binding_id}` **仍然只停用**。彻底删除先调用 `GET /api/v1/tenants/{tenant_id}/resources/channel-bindings/{binding_id}/deletion-preview`，再调用同资源的 `DELETE .../purge`，请求体为 `{"confirmation":"预览要求的完整名称"}`。具体阻挡条件、收据与清理重试见 [配置停用与删除](配置停用与删除.md)。不要用删除绕过 UNKNOWN 投递核对。

## 验收和排障

| 现象或检查 | 排查顺序 |
| --- | --- |
| 保存时 409 | Agent/模型是否可执行；应用账号是否已被其他活跃 Binding 占用 |
| 保存成功但没有认证日志 | Channel 进程、租户/Agent/Adapter/Binding 启停状态、Secret、网络；再查 connection failed 日志 |
| 已认证但收不到私聊 | 飞书消息事件订阅、应用已发布版本、权限、测试用户的可用范围 |
| 私聊正常，群聊无响应 | 机器人是否在群中、是否明确提及、群聊事件权限 |
| 有提示但无最终答案 | `agent_task`、Worker、模型/工具错误、`outbox_message`、`outbox_attempt` |
| 普通回复可用，开启流式失败 | Binding 的 streaming 必须为布尔值 true；检查 CardKit 权限及 SDK/API 错误 |
| 图片/文件无响应 | 资源下载权限、媒体大小、对象存储、入站处理错误、模型/解析器能力 |
| 后续回复一直等候 | 是否存在同回复流的前序 UNKNOWN，先核对其实际送达情况 |

验收建议依次做私聊文本、群聊提及、线程、图片/文件、停用后启用。重复回调按外部 message_id 去重；用户重新发相同文字通常产生新 ID，应该正常回复。

明确可重试失败会有限重试；结果不明或投递租约过期转 UNKNOWN。核实已收到后“确认已送达”只更新状态，核实未送达再决定重新投递。入口与规则见 [故障运维与恢复](故障运维与恢复.md)。

已有真实人工验收见 [测试结果](测试结果.md)。当前没有飞书线上强制断连的自动化验收结论，也没有把本次文档核对算成新的联调。
