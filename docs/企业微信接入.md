# 企业微信接入

核对日期：2026-10-06，代码基线 `89d213d`。本页按当前代码说明接入、配置和恢复方法。本次为文档核对，没有重新连接真实企业微信账号或调用模型。

## 接入方式与前提

项目接入的是企业微信**智能机器人 API 模式长连接**，通过 `wecom-aibot-sdk` 收发消息。它与群机器人的 Webhook 地址、企业自建应用的 HTTP 回调不是同一套接入方式，不能混用凭据。

长连接由 Channel Runtime 持有。消息写入 PostgreSQL 队列后，Worker 执行模型和工具，将结果提交到 Outbox，再由 Channel Runtime 投递回复。普通 Worker 不持有机器人连接。

需要准备：

- 企业微信智能机器人的 Bot ID 和 Secret，并选择长连接模式。
- 平台侧启用的租户、可执行的 Agent、可用模型策略，以及启用的企业微信 Adapter 和 Binding。Binding 是机器人账号与租户 Agent 的绑定记录。
- Channel Runtime 能访问企业微信 WebSocket 和媒体接口，Worker 能访问模型服务，文件处理能访问对象存储。

不需要公网回调地址，也不需要向企业微信开放本机 8000 端口。默认租户控制台是 `http://127.0.0.1:8000/tenant`；修改过监听端口时使用实际地址。使用 `start.sh` 启动 Gateway、Worker Supervisor 和 Channel Runtime，单独启动 API 无法收发机器人消息。

## 企业微信侧配置

1. 在企业微信客户端的智能机器人入口创建机器人，选择 API 模式和长连接方式。
2. 保存 Bot ID 和 Secret，确认机器人对测试用户可用；群聊测试还需将机器人加入测试群。
3. 在项目中创建下文的 Binding，等待认证成功，再分别测试私聊和群聊提及。

本项目表单需要 `bot_id` 与 `bot_secret`，不需要填 Corp ID、HTTP 回调 Token 或 EncodingAESKey。消息附件中用于解密媒体的密钥由消息协议携带，不是这里需要手工配置的机器人凭据。

企业微信侧的创建入口可参考[腾讯云官方接入说明](https://cloud.tencent.com/document/product/1831/137051)。该文包含 WorkBuddy 自身配置，本项目只参考其中的企业微信侧操作；平台配置以本页字段为准。

## 在项目中配置

进入 `/tenant` 的“IM 接入”，选择企业微信和 Agent，填写 Bot ID、Bot Secret 后保存。默认配置同步间隔为 5 秒，可由 `TRPC_SERVICE_CHANNEL_RECONCILE_INTERVAL_SECONDS` 调整；同步间隔不代表连接一定能在 5 秒内认证完成。

| 字段 | 位置 | 用途与实际行为 |
| --- | --- | --- |
| `bot_id` | `account_config` | 必填，智能机器人 Bot ID |
| `bot_secret` | `secret_values` | 创建时提供的只写密钥，由租户 SecretStore 加密保存 |
| `thinking_message` | `account_config` | 可选，最长 200 字符；设为 `""` 关闭处理中提示 |
| `max_inbound_media_bytes` | `capabilities` | 单条消息下载媒体的累计字节上限，默认 52,428,800 字节，即 50 MiB；需为正整数 |

表单 Schema 中提示语的默认值为“正在思考，请稍候…”，适配器在字段完全缺省时使用“正在思考...”。建议显式填写。提示在任务可靠入队后尽力发送；失败不会撤销任务，也不能把这一机制理解成任何消息都保证 1 秒内可见。

当前租户表单没有单独的媒体上限控件，调整时使用 Binding API。企业微信文本回复使用 SDK 的 `reply_stream`，无需套用飞书的 `capabilities.streaming` 开关。

### API 配置示例

以下是请求体示例，UUID 和凭据均需替换。默认 API 前缀 `/api/v1`；请求需要管理认证，Cookie 登录还需按控制台机制携带 CSRF 信息，见 [管理员模块设计](管理员模块设计.md)。

`POST /api/v1/tenants/{tenant_id}/channel-bindings`

```json
{
  "agent_app_id": "00000000-0000-0000-0000-000000000001",
  "channel_type": "wecom",
  "account_config": {
    "bot_id": "替换为机器人BotID",
    "thinking_message": "已收到，正在处理。"
  },
  "secret_values": {
    "bot_secret": "替换为机器人Secret"
  },
  "capabilities": {
    "max_inbound_media_bytes": 52428800
  }
}
```

轮换 Secret 使用 `PATCH /api/v1/tenants/{tenant_id}/channel-bindings/{binding_id}`：

```json
{
  "secret_values": {
    "bot_secret": "替换为轮换后的机器人Secret"
  }
}
```

不改密钥时省略 `secret_values`，不要提交空字符串或星号占位符。`secret_values` 与 `secret_ref_map` 不能同时提交。查询只返回已配置的 `secret_fields` 名称，不回显密钥或内部存储引用。保留 `.secrets/tenant_secret_master_key`，否则已有租户密文可能无法解密。

通常不需要提交 `external_account_hash`，服务会从机器人身份生成。一个活动外部机器人账号不能同时绑定到两个活动 Binding。PATCH 的 account_config、capabilities 是整块替换，不是递归合并；修改提示语时仍需带上 bot_id，修改媒体上限时也应保留其他 capabilities 设置。

## 如何确认已经接通

Binding 显示 active 只表示配置启用，Channel Runtime 心跳也只证明进程在运行。使用 `start.sh` 时，在 `.run/channel-runtime.log` 中按 binding_id 查找 `WeCom binding authenticated`，才说明对应机器人已认证。

租户、Agent、Adapter 或 Binding 任何一个被停用，都会使该连接不再属于运行目标。修改密钥后 Runtime 会重建连接，需再次确认认证日志。断连时会出现 `WeCom binding disconnected`；SDK 的重连成功也应以新的认证事件为准。

私聊按发送用户映射会话，群聊按群 ID 映射，再叠加租户与 Binding 范围。同一群里多个机器人不会因为群 ID 相同就共享会话。收到的 aibotid 必须与 Binding 的 bot_id 一致，否则会拒绝处理。

## 回复、去重与断连恢复

入站 `acknowledge` 是适配器内部的逻辑接受结果，不是要求用户配置的 HTTP 回调。任务可靠入队后，处理中提示以 `finish=false` 打开回复流。Worker 汇总答案并提交 Outbox 后，最终文本使用同一个 stream_id，以 `finish=true` 结束回复。

这里不是模型每生成一个 token 就推送给企业微信。stream_id 由 Binding 和外部消息 ID 稳定生成，用于关联回复流；它本身不能证明外部投递严格只发生一次。

同一 Binding 下，相同外部消息 ID 的重复回调会被去重。用户重新发送相同文字通常会得到新的消息 ID，属于新任务，应该再次回复。

明确可重试的失败会有限重试。发送结果不明，或投递已进入 PROCESSING 但租约到期且没有成功记录时，会转为 UNKNOWN，暂停同回复流的后续投递。这样避免对方已收到消息后系统又盲目重发。管理员核实已送达后可“确认已送达”，此操作只更新状态；核实未送达后再决定重新投递，人工重投仍需考虑重复风险。操作入口和规则见 [故障运维与恢复](故障运维与恢复.md)。

## 图片、文件与大小限制

入站适配器解析文本、图片、混合消息、文件、语音和视频描述。单个文本片段最多 20,000 字符，混合消息最多 20 个条目；这不是所有混合文本合并后的统一 20,000 字符限制。

媒体通过 SDK 下载，再写入租户 Artifact 空间。默认 50 MiB 是单条消息中已下载媒体的累计校验，不是下载前就能阻止全部网络流量，也不是企业微信所有接口的统一上限。下载和存储发生在入队前，大文件可能延迟首次提示。

图片理解取决于视觉模型配置，文件内容取决于解析器支持。能接收语音、视频描述，不等于已实现转写或视频理解。租户使用哪个模型由模型策略决定，不由 `.env.example` 中的示例名称固定。

## 停用、轮换与彻底删除

- **临时断开：** 停用 Binding，Runtime 同步后断开长连接，配置和历史保留。重新启用前会检查 Agent 是否可执行。
- **轮换 Secret：** 更新原 Binding 的密钥，等待新的认证日志后测试。
- **更换 Bot ID：** 建议先停用旧绑定，再创建新 Binding，避免账号身份与历史会话混淆。新 Binding 使用新的会话映射范围。
- **彻底删除：** 处理未完成任务和投递，停用后打开删除预览，按预览要求输入完整名称。删除会清理接入专属记录与不再被其他接入引用的租户密钥，不会删除企业微信侧的机器人或撤销其 Secret。

旧的 `DELETE /api/v1/tenants/{tenant_id}/channel-bindings/{binding_id}` **仍然只停用**。彻底删除先调用 `GET /api/v1/tenants/{tenant_id}/resources/channel-bindings/{binding_id}/deletion-preview`，再调用同资源的 `DELETE .../purge`，请求体为 `{"confirmation":"预览要求的完整名称"}`。不要用删除绕过 UNKNOWN 投递确认。阻挡条件、清理收据和重试见 [配置停用与删除](配置停用与删除.md)。

## 验收和排障

| 现象或检查 | 排查顺序 |
| --- | --- |
| 保存时 409 | Agent/模型是否可执行；Bot ID 是否已被其他活跃 Binding 占用 |
| 保存成功但没有认证日志 | Channel 进程、四类配置启停状态、Bot ID/Secret、企业微信长连接模式、网络 |
| 已认证但收不到消息 | 测试用户是否可访问机器人；群聊中是否已加入并提及机器人 |
| 有提示但没有最终答案 | `agent_task`、Worker、模型/工具错误、`outbox_message`、`outbox_attempt` |
| 图片/文件不响应 | 入站下载错误、累计大小、对象存储、模型和解析器支持范围 |
| 断连后回复停住 | 是否已重新认证；待投递记录状态；同回复流是否存在前序 UNKNOWN |
| 同样的问题回复了两次 | 先核对外部消息 ID，区分用户重新提问与同一消息被重复投递 |

验收依次检查私聊文本、群聊提及、图片/文件、停用后启用。断连测试需同时检查连接事件、任务数量和最终回复，不能只凭“重连后能再次提问”推断所有旧消息均已恢复或完成去重。

已有真实 IM 人工验收与 SDK 模拟服务端断连测试分别记录在 [测试结果](测试结果.md)。后者使用真实 SDK 对接本地 WebSocket 测试服务，验证重连和回调重放路径，不代表企业微信线上故障恢复时延。本次文档核对没有新增这些测试的结论。
