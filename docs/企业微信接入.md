# 企业微信接入

## 接入方式

当前使用企业微信智能机器人 API 模式长连接，由 `wecom-aibot-sdk` 接入，不需要公网回调地址。支持私聊和群聊提及机器人。入站适配器解析文本、图片、混合消息、文件、语音和视频描述；接收媒体不等于具备对应的语音识别或视频理解模型能力。

一个 Channel Runtime 同时管理各租户 Binding 和飞书连接。普通 Agent Worker 不持有机器人连接，只执行队列任务并生成回复 Outbox。

## 配置

1. 在企业微信创建 API 模式长连接智能机器人，取得 Bot ID 与 Bot Secret。
2. 在平台中准备启用的租户 Agent 和可用 Model Profile。
3. 租户管理员进入 `/tenant` 的 IM 接入，选择企业微信，填写 Agent、Bot ID 和 Bot Secret，启用 Binding。
4. 等待 Channel Runtime 同步配置，检查连接错误和心跳，再向机器人发送文本。

Bot ID 是账号配置；Bot Secret 写入租户加密存储，接口不回显。一个活动外部机器人账号不能同时绑定到两个活动 Binding。迁移账号时先停用旧 Binding，保留可恢复的原配置。

`thinking_message` 是可选的处理中提示，不是凭据，默认“正在思考...”，空字符串关闭。它在任务可靠入队后尝试发送；发送失败不撤销任务。媒体下载在入队前，首次提示时间可能比纯文本更长。

## 回复与恢复

Adapter 调用 `acknowledge` 返回逻辑接受结果，然后 `send_progress` 打开未结束的回复流。Worker 汇总结果并提交 Outbox 后，Delivery Worker 通过原 Binding 连接发送最终回复。这里不是模型 token 逐个直通 IM 的实时通道。

明确连接失败、限流等按投递策略处理。发送结果不明，或 PROCESSING 租约到期而没有成功记录时，进入 UNKNOWN。租户控制台可在核实后“确认已送达”，该动作只更新状态，不重发；核实未送达才决定重新投递。详细规则见[故障运维与恢复](故障运维与恢复.md)。

## 文件与图片

文本内容限制为 20,000 字符，媒体累计默认最多 50 MiB，可通过 Binding 下调。下载后的文件先写入租户 Artifact 空间，不能直接用外部地址作为模型任意读取入口。

图片按模型适配路径和视觉模型配置处理；文本使用租户模型配置。不要把 `.env.example` 中的 `qwen-max`、`qwen-vl-max` 当作所有租户固定使用的模型，也不要把媒体可接收写成所有媒体都可理解。

## 验收与排查

| 检查 | 预期 |
| --- | --- |
| 私聊文本 | 任务入队后提示，最终收到结果 |
| 群聊提及机器人 | 群会话与私聊分开，同一群的不同 Binding 不串上下文 |
| 同一消息 ID 重复回调 | 队列去重；相同文字但新消息 ID 正常形成新任务 |
| 图片或文件 | 能在本租户 Artifact 中定位，并按已配置模型或解析器处理 |
| 停用再启用 Binding | Runtime 同步后断开、重新建立连接 |
| 有提示但无回复 | 依次查任务、Worker、模型错误、Outbox 与投递 Attempt |

已经完成的真实 IM 人工测试与 SDK 模拟服务端断连测试分开记在[测试结果](测试结果.md)。后者证明重连和回调重放路径，不是企业微信线上服务端的故障恢复时延。
