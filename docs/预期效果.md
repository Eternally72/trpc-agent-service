# 预期效果

## 1. 功能效果

- 平台管理员可以为多个租户分别分配模型、凭据、参数、预算和 Worker 容量；租户按授权使用 Agent、Tool、Skill、MCP 和 IM 通道。
- 企业微信和飞书使用同一套 Agent 执行链路，不需要重复实现 Session、Memory 和治理逻辑。
- 任意 Worker 都可以继续处理已有 Session，节点扩容和重启不影响会话归属。
- PostgreSQL、向量库和对象存储各自保存适合的数据，并可以通过 Adapter 替换；Redis 启用时只承担可重建的协调能力。
- 管理员可以按租户发布或回滚配置，不影响其他租户。
- 租户管理员可以在 Web 管理台新增、替换和删除知识；IM 对话者只能通过授权 Agent 检索，同租户可共享，其他租户无法读取。
- 租户管理员可以接入自己的 HTTPS Streamable HTTP MCP，凭据只写不读，远程工具仍经过权限、审批、Ledger 和审计。

## 2. 安全效果

- 跨租户数据访问被拒绝，配置、缓存、向量索引、对象路径和审计数据都有租户边界。
- 未授权 Tool 不能执行，危险 Tool 必须二次确认。
- IM Token、模型 API Key 和数据库密码不会出现在代码、响应、日志、Trace 或错误报告中；租户 IM 密钥以密文保存。
- 重复消息和失败重试不会重复产生外部副作用。

## 3. 运行效果

| 验收项 | 目标 |
| --- | --- |
| 自动化测试 | 格式、Lint、类型、Migration 和单元测试全部通过，总体覆盖率不低于 90% |
| 租户隔离 | 跨租户验收用例全部拒绝 |
| 重复副作用 | 重复、乱序和重试用例中为 0 |
| Trace 覆盖 | 核心链路覆盖率不低于 95%，错误和危险 Tool 全量采样 |
| IM 回复 | 24 小时 Outbox 最终投递成功率不低于 99.5% |
| 配置回滚 | 租户配置在 5 分钟内回滚生效 |
| 故障恢复 | 单区域 RTO 不超过 15 分钟，核心 SQL RPO 不超过 1 分钟 |

## 4. 当前效果

当前已经具备完整 Agent 主链路、无状态 Worker、平台集中模型配置、Usage/Tool Ledger、统一 Capability Grant、L2/L3 二次确认、配置化存储、追加式审计、租户级 RAG、Local Workspace、知识型 Skill、租户 MCP 和完整身份/Conversation 模型。企业微信和飞书已接入真实长连接；系统管理台与租户工作台使用独立入口，分别覆盖平台治理与租户 Agent、IM、知识库、MCP 管理。

当前自动化结果为 387 passed、2 skipped、覆盖率 90.25%，源码格式、Flake8、严格 mypy、Alembic 单一 Head 和 Python 制品构建均已通过。Docker Desktop Kubernetes 清单已经具备完整部署能力，本轮真实 IM、组件和 Kubernetes 截图由人工验收补齐。生产上线前仍需接入外部 Secret Manager、Ingress TLS、高可用存储、告警接收端和离机备份策略。
