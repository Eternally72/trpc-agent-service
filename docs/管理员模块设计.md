# 管理员模块

## 两类身份

平台管理员使用 `/admin`，租户管理员使用 `/tenant`。两个页面由同一个 Gateway 提供，授权由后端检查，不能依赖前端隐藏按钮。

每个租户只有一个租户管理员登录身份。企业微信、飞书中与机器人对话的人属于渠道 Principal，不进入后台账号角色体系。

| 资源 | 平台管理员 | 租户管理员 |
| --- | --- | --- |
| 租户、后台账号 | 创建租户、创建唯一租户管理员、重置密码 | 不管理其他租户 |
| 模型目录、凭据、Profile | 维护模型、供应商凭据和租户预算 | 选择分配给本租户的可用模型配置 |
| Agent 与能力 | 在支持模式下进入租户范围 | 管理本租户 Agent，授权具体 Tool、Skill、MCP 和知识库 |
| IM Binding | 支持排查，不回显密钥 | 维护本租户机器人账号、密钥与启停 |
| 知识文档 | 通过受审计的租户支持访问 | 上传、替换、删除本租户获准知识库文档 |
| MCP | 平台控制出站边界 | 保存连接、刷新目录、配置具体工具授权 |
| 投递恢复 | 支持模式下核对与操作 | 查看 UNKNOWN/死信，确认已送达或决定重放 |
| Worker Pool、平台用量与审计 | 查看运行状态、设置期望节点数、查询用量 | 不管理全局运行资源 |

平台访问租户范围需要至少 12 字符的 `X-Support-Reason`，并记录支持访问审计。它不是不受限制的隐式超级权限入口。租户接口依然检查资源归属。

## 模型配置

配置关系为：模型目录 + 同供应商活动凭据 → 租户 Model Profile → Agent。模型 API Key 由平台管理，不由租户 IM 对话者提供。

Profile 保存生成参数、输出与上下文上限、超时、单价及每日配额。`daily_calls`、`daily_tokens` 使用 UTC 自然日。启用 Token 硬预算时要求 `daily_tokens >= context_window_tokens >= max_output_tokens`。

执行前预留预算，完成后按实际返回用量结算。Usage Ledger 以租户和请求 ID 幂等记录，不以 Prometheus 计数代替账本。平台估算成本不等于供应商账单；已有人工核对缺少统计周期和总量，没有百分比误差结论。

Agent 配置保存为不可变版本。发布或回滚切换稳定/灰度指针，入队任务仍使用当时选择的版本。

## 租户配置顺序

1. 创建启用的 Agent，选择活动 Model Profile。
2. 授权内置 Tool 和审核过的 Skill。Skill 只加载文字步骤，不执行脚本。
3. 为知识库配置授权名称，再在管理页面上传、替换或删除文档。IM 侧只有列表与检索工具。
4. 如需 MCP，先保存连接并刷新目录，再给 Agent 勾选具体工具。连接刷新成功不意味着 Agent 自动获得全部工具。
5. 绑定企业微信或飞书账号。Binding 创建与切换 Agent 时会检查目标 Agent 是否可用。

机器人 Secret 和 MCP Bearer Token 为只写字段，由主密钥按租户加密保存。空白输入、轮换和保留旧值的具体行为由各接口 Schema 决定，不应通过查询接口尝试读取明文。

## 投递失败页面

控制台支持两种不同操作：

- **确认已送达**：仅适用于 UNKNOWN，填写核实依据，可附服务商回执。更新 Outbox 和 Inbox，追加审计，不发送消息，原 Attempt 仍保留 UNKNOWN。
- **重新投递**：适用于 UNKNOWN 或 DEAD_LETTER。重置本轮重试预算，保留历史尝试次数。对结果不明的记录重发可能重复送达，应先核实。

后端再次校验当前状态、租户、认证和理由，重复确认不会再次成功。页面操作规则及 API 见[故障运维与恢复](故障运维与恢复.md)。

## Worker Pool

运行节点页面修改 `desired_nodes`，请求携带 generation，防止旧页面覆盖新设置。Web 请求不直接创建或强杀进程。

本地 Supervisor 创建缺少的 Worker，缩容先让多余节点停止领取任务，再等待排空。Kubernetes Scaler 只操作 `agent-worker` 的 scale 子资源。节点数和每节点 slot 数不是同一个配置，具体差别见[架构](架构.md)。

## 认证与审计

人员密码采用 Argon2id，浏览器登录使用可撤销服务端 Session、HttpOnly Cookie 和 CSRF 检查，并有登录限流与临时锁定。Bootstrap Token 保留作初始化和应急管理，不代替日常人员账号。

生产部署需要 HTTPS 并启用安全 Cookie；本地配置允许 HTTP，不能直接据此声称已经完成生产 TLS 防护。配置变更和恢复操作记录操作者、资源、原因及安全摘要，真实密钥不能进入响应或审计详情。
