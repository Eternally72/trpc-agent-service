## 请求输入保护

普通管理接口默认只接受 1 MiB 请求体，可通过 `TRPC_SERVICE_HTTP_MAX_BODY_BYTES` 配置。检查在 JSON 解析之前执行，同时校验声明长度和实际分块累计长度，不能通过省略或伪造 Content-Length 绕过。普通请求体接收最长 30 秒；超量返回稳定的 413 错误，超时返回 408。

知识文件创建与替换保留独立的 10 MiB 上限，继续在鉴权后流式读取，并由知识服务检查每个数据块。上传放宽规则按路径和 HTTP 方法匹配，伪造 Content-Type 不能提高登录等管理接口的额度。异常处理器现在保留 `Retry-After` 等响应头，登录限流可向客户端说明等待时间。

## 存储准备与运行检查

运行进程不再自动执行 pgvector DDL 或 S3 建桶。`StorageComposition.initialize()` 只校验向量表维度、查询权限和 bucket 可达性。缺失或不兼容的基础设施会阻止启动，避免把缺失状态伪装成就绪。

部署顺序为：

```bash
uv run alembic -c trpc_service/storage/alembic.ini upgrade head
uv run python -m trpc_service.storage.provision
# 完成准备后再启动 API、Worker、Channel 和 Supervisor
```

`start.sh` 和 Kubernetes migration Job 已纳入第二步。无需手工重复执行。独立准备步骤具有幂等性，并在成功、验证失败时关闭 SQL、embedding 和 S3 客户端。S3 连接超时为 5 秒，读取超时为 30 秒，使用有界 SDK 重试。

生产环境应为准备步骤提供迁移身份，为应用提供只有运行所需权限的身份；本仓库本地 Docker/Kubernetes 示例仍使用共享开发凭据。本轮解除应用启动对 DDL/建桶权限的依赖，没有声称已替生产环境创建最小权限账号、配置 TLS 或发布 Kubernetes。

## 前端交互

沿用两个控制台的既有视觉体系，增加明确的加载中/加载失败状态、重复刷新合并及按钮恢复。加载时锁定当前视图筛选，暂停表格操作；失败后允许刷新或重选筛选，但旧表格保持不可操作，避免使用不匹配的租户/Agent 参数。成功后恢复操作。运行状态显示中文文案，同时保留底层状态值与权限判断。补齐模型、凭据、策略和适配器导航图标；手机端指标改为两列，缩短首次查看概览所需的滚动距离。

API、前端静态文件和 `/console/config.js` 仍由同一进程提供，本地端口为 `8000`，没有引入独立前端服务。
