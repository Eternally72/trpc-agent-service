# 时间规划

本项目按进度 Gate 管理，不按天数拆分。功能实现完成不等于生产环境就绪；每个 Gate 同时记录代码状态和外部上线条件。

## 进度一：工程与控制面基线

状态：已完成。

- uv 锁定依赖，根目录脚本负责构建、启停、格式、Lint 和覆盖率。
- 完成 Tenant、Agent、Model Catalog/Profile/Credential、Channel Adapter Type 和基础 CRUD。
- 完成平台/租户独立登录入口、唯一租户管理员账号、RBAC、CSRF 和管理审计。

退出结果：新环境可通过脚本初始化，控制面资源具备租户隔离和密钥引用边界。

## 进度二：共享状态与多节点

状态：已完成。

- PostgreSQL 保存 Session、Event、Inbox、Outbox、Agent Task 和 Worker Pool 期望状态。
- Session FIFO、行锁领取、lease generation、fencing token、续租和节点接管已实现。
- 本地 Supervisor 和 Kubernetes Scaler 使用相同的期望状态扩缩容语义；缩容先排空。

退出结果：Worker 不依赖 sticky session，重复、乱序和节点中断不会绕过数据库事实状态。

## 进度三：Agent 与能力闭环

状态：已完成主体能力。

- tRPC-Agent Runner、百炼模型、Session/Memory、RAG、通用 Tool 和 Tool Ledger 已接入。
- Local Workspace、Runner Attempt/Checkpoint、持久化审批和 UNKNOWN 隔离已接入。
- Skill 使用 knowledge-only 模式；MCP 由租户配置，按 Agent 授权并进入统一治理。

保留增强项：超过 10 MiB 的知识文件改为异步摄取；Memory/Summary 的独立异步投影和外部存储迁移工具按规模启用。

## 进度四：真实 IM

状态：已完成企业微信与飞书接入。

- 两种 IM 均通过抽象 `ChannelAdapter` 进入统一身份、Conversation、Inbox、任务队列和 Outbox 链路。
- 支持长连接、快速 ACK、文本、图片/文件处理、去重、重试和失败恢复；飞书使用 CardKit 流式卡片，企业微信使用回复流。
- Bot/App ID 与密钥由租户管理台按 Adapter Schema 配置，不在代码或示例文件中硬编码。

退出结果：真实账号可以使用同一 Agent 主链路；新增 IM 只实现 Provider 协议，不复制 Agent 逻辑。

## 进度五：治理、监控与运维

状态：本地和代码侧已完成。

- Capability Grant、预算、脱敏、审批、Usage Ledger、Audit 和配置灰度/回滚已完成。
- OpenTelemetry、Prometheus、Grafana、Tempo、Loki 和 Alloy 已纳入 Compose 与 Kubernetes。
- 备份、恢复、容量、Smoke 和真实组件检查脚本保留在本地 `dev/`，不进入上游 PR。

外部条件：生产告警接收端、外部 Secret Manager、日志/Trace 保留策略和离机备份位置需在部署环境确定。

## 进度六：验收与上线

状态：自动化已通过；真实 IM、组件与本地 Kubernetes 截图待本轮人工验收，生产上线条件待环境落实。

- 当前自动化基线：396 passed、2 skipped、覆盖率 90.23%。
- 格式、Flake8、严格 mypy、Alembic Head 和 wheel/sdist 构建已通过。
- 真实存储组件、企业微信、飞书、RAG、管理台和 Kubernetes 按测试文档重新验收并补充截图。

正式上线 Gate：完成域名/TLS、生产密钥托管、高可用 PostgreSQL/S3、告警接收、离机备份恢复、安全扫描、容量压测、灰度发布和回滚演练，且不存在 P0/P1 问题。
