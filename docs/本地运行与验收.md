# 本地运行与验收

## 准备环境

需要 Python 3.12、uv、Docker Compose，以及 `curl`、`openssl`、`setsid`。应用运行在主机 Python 中，Compose 只运行 PostgreSQL/pgvector、Redis、SeaweedFS 和监控组件。

首次配置时复制示例；已有 `.env` 不要覆盖：

```bash
cp .env.example .env
```

`.env.example` 中的模型名是示例，不代表账户当前可用模型。文本模型以平台分配给租户的 Model Profile 为准；图片路径还使用视觉模型配置，知识向量由 `TRPC_SERVICE_EMBEDDING` 配置。使用示例中的环境变量凭据引用时，需要在本地设置 `DASHSCOPE_API_KEY`。

当前向量列固定为 1024 维。更换 Embedding 模型需要重建对应知识库索引，原知识库模型名不一致时会拒绝摄取或检索；不能只修改名称后继续使用旧向量。真实 LLM 压测使用过 `qwen3.7-flash`，这不是服务硬编码的唯一模型。

## 启动与端口

```bash
./start.sh
```

脚本依次构建制品、启动基础设施、执行迁移和存储准备，再启动 Gateway、Channel Runtime、Supervisor 与 Worker。首次 Worker Pool 默认 2 个节点，每节点 1 个 slot；后续节点数遵循管理端保存的期望值。

| 入口 | 默认本机地址 | 配置或说明 |
| --- | --- | --- |
| 平台管理端 | `http://127.0.0.1:8000/admin` | 与 API 共用 `TRPC_SERVICE_PORT` |
| 租户管理端 | `http://127.0.0.1:8000/tenant` | 与 API 同源，不存在独立前端开发端口 |
| 健康与就绪 | `http://127.0.0.1:8000/health`、`/ready` | 存活与就绪分开检查 |
| Grafana | `http://127.0.0.1:3000` | 用户名 `admin` |
| Prometheus | `http://127.0.0.1:9090` | 运行指标 |
| PostgreSQL | `127.0.0.1:55432` | Compose 宿主端口，容器内为 5432 |
| Redis | `127.0.0.1:6379` | 近期 Session 缓存 |
| SeaweedFS S3 | `http://127.0.0.1:8333` | 本地对象存储入口 |

应用端口通过 `TRPC_SERVICE_PORT` 调整，前端调用使用同源地址。Compose 各宿主端口由 `compose.yaml` 的 `TRPC_*_PORT` 变量决定；自定义端口后还需核对 `.env` 中缓存、向量库和对象存储地址。启动脚本会读取 PostgreSQL 实际发布端口设置主数据库连接。

启动会在 `.secrets/` 中首次生成数据库密码、平台 Bootstrap Token、租户 SecretStore 主密钥和 Grafana 密码，重启沿用。不要删除主密钥后继续使用原数据库，否则租户 IM/MCP 密文将无法解密。

## 首次配置顺序

1. 访问 `/admin`，使用 `.secrets/admin_bootstrap_token` 中的 Bootstrap Token 完成平台管理初始化，配置日常管理账号。
2. 创建模型目录与平台模型凭据，创建租户及该租户唯一管理员账号，为租户分配 Model Profile。
3. 租户管理员登录 `/tenant`，创建启用的 Agent，选择可用模型，授权 Tool、Skill、知识库或 MCP。
4. 创建企业微信或飞书 Binding，填写机器人 ID 和只写密钥。Binding 只能指向已就绪的 Agent。
5. Channel Runtime 轮询配置后建立长连接。先验证文本问答，再验证知识检索与 MCP，避免把连接、授权和模型错误混在一起排查。

IM 与 MCP 密钥由租户控制台写入数据库密文，不需要写入代码或截图。MCP “测试并刷新”只完成发现；还需要在目标 Agent 上勾选具体工具。

## 最小验收

```bash
curl --fail --max-time 5 http://127.0.0.1:8000/health
curl --fail --max-time 5 http://127.0.0.1:8000/ready
```

然后完成以下检查，保留具体请求和结果：

| 操作 | 检查内容 |
| --- | --- |
| IM 发一条文本 | 先出现处理提示，随后收到最终结果；队列任务与 Outbox 均能查到 |
| 再发一句依赖上文的问题 | 同会话能使用历史，另一机器人不继承这段上下文 |
| 上传一份独有知识文档并提问 | 返回自身知识库内容和来源；更新或删除后重问 |
| 授权 GitHub MCP 后查询仓库 | 区分是否调用工具与答案是否准确，检查 Tool Ledger |
| 修改 Worker 期望数量 | 节点心跳随扩缩容变化，缩容节点先排空 |

这些是验收步骤，不代表运行命令后自动证明全部通过。已完成测试的条件见[测试结果](测试结果.md)。

## 停止与日志

```bash
./stop.sh
```

普通停止保留数据。`./stop.sh --volumes` 用于明确要删除本地测试数据时，会清理持久数据，不作为日常重启命令。

Gateway 日志在 `.run/trpc-agent-service.log`，Channel 在 `.run/channel-runtime.log`，Supervisor 在 `.run/worker-supervisor.log`，Worker 日志也在 `.run/`。优先用 `request_id`、`trace_id`、任务 ID 和安全错误码定位，避免复制整段消息正文或凭据。

## 开发检查

```bash
./format.sh --check
./lint_flake8.sh
uv run mypy trpc_service
./coverage.sh
./build.sh
```

默认 pytest 只收集 `tests/`，`coverage.sh` 仍要求 90% 覆盖率。历史 90.19% 包含本地额外用例，不能当作当前默认入口已经通过。

本地保留额外回归时，可以显式运行：

```bash
uv run pytest tests dev/tests/test_reliability_regressions.py
```

`dev/` 全部不提交 Git，克隆仓库不保证存在该路径。压测和故障注入需要专用数据库与显式模型额度，不能直接对日常租户执行清理；本页不自动启动这些测试。
