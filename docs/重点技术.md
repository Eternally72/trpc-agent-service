## 请求作用域与租户隔离

`TenantContext` 带有 `tenant_id`、`agent_app_id`、`config_version`、`request_id` 和 `trace_id`。业务查询、组合外键、缓存键、知识来源过滤及对象位置共同约束租户范围。

Agent 的模型、Tool、Skill 和 MCP 按请求装配，使用入队时固定的配置版本。平台不将某个租户的 Tool 实例作为其他租户可用的全局工具。IM 外部账号先映射为渠道身份，再关联 Session；后台管理账号不直接充当 IM 用户。

人工隔离测试与两个租户复用同一外部消息 ID 的自动化测试已经完成，但租户资源竞争仍然存在。授权隔离、数据隔离与性能隔离需要分别讨论。

## Worker、租约和 Workspace

每个 Worker 启动 `concurrency` 个异步 slot，同一 slot 依次处理任务。任务领取在 SQL 中完成，遵循 Session FIFO，并用递增任务 token 校验续租、成功和失败操作。Pipeline 另外持有 Session fence，最终写入还检查会话版本。

Workspace ID 包含 Session、请求和当前执行 fence。旧进程暂停后继续持有的文件锁只影响旧目录。新进程不能把本地临时目录当作持久事实，也不通过删除锁文件接管。目录内只开放受授权的列表与有限 UTF-8 文本读取，不能把这个目录隔离描述成容器沙箱。

相关代码：[Worker](../trpc_service/agent/worker.py)、[Pipeline](../trpc_service/agent/pipeline.py)、[Workspace](../trpc_service/workspace/local.py)。

## Session 缓存

PostgreSQL 保存完整会话事实。Redis 保存带租户和 Agent 范围、Session 版本、TTL 和事件数上限的近期快照。执行协调器取得 SQL 当前版本后才尝试缓存；版本不一致、条目损坏或连接失败时回源，提交成功后才更新缓存。

Runner 将保存的 `message.received`、`agent.replied` 恢复为原有 user/model 轮次。本轮输入单独传入，不把整段历史拼成一条新的 user 消息。Memory、Summary 通过独立 Port 读取；当前没有每轮自动抽取长期 Memory 的流程。

## RAG 文档生命周期

管理 API 同步处理 TXT、Markdown、PDF、DOCX，文件上限 10 MiB。文本默认按 1,200 字符切片、重叠 200 字符，解析还受页数、展开大小和提取字符数约束。原文件进入 S3，元数据和文档状态进入 PostgreSQL，向量进入 pgvector。

更新时先写新向量，再提交新版本 READY 和旧版本 SUPERSEDED。检索候选返回前，按租户、授权知识库和 SQL READY 来源再次筛选。删除先提交 DELETED，再尝试清理向量。向量清理失败不使旧知识重新可见，但原始对象和元数据仍可能保留。

`BailianEmbeddingConfig.dimensions` 目前固定为 1024，批量上限 10。示例模型仍是 `text-embedding-v4`，实际可用模型以本地配置为准。更换模型需要重新索引对应知识库，即使新模型同为 1024 维也不能混用两套语义空间。现有知识库模型名与配置不一致时会明确报错。

相关代码：[知识服务](../trpc_service/storage/knowledge.py)、[Embedding 配置](../trpc_service/config/llm.py)、[向量适配器](../trpc_service/storage/adapters/pgvector.py)。

## MCP 的发现、授权与调用

租户创建 HTTPS Streamable HTTP 连接，Bearer Token 加密保存。刷新目录只确认连接和工具清单；Agent 还需显式授权具体连接、工具、动作和资源。

当前实现使用 tRPC `MCPToolset`，通过 `GovernedMCPTool` 将执行接入 Capability Grant、审批、Tool Ledger 和审计。工具声明严格只读且未声明破坏性时按 L0 处理，其余保守按 L2 确认。旧目录可重发现，运行时风险分类覆盖旧快照中的分类，客户端不能直接把远端写工具降级。

传输层先限时解析并校验地址，再固定连接到已验证 IP，保留原 HTTPS Host 与 SNI。客户端禁用环境代理继承和自动重定向，仅对发送前的连接失败尝试其他已验证地址。读写阶段失败不能直接换地址重发，否则可能重复执行远端写操作。

两项 GitHub 联调修正已经进入实现：

1. 转发 HTTPX 请求时保留异步 `request.stream`，避免重新编码为同步流后无法完成异步请求。
2. 给仓库搜索工具补充 fork 查询提示：指定用户搜索可用 `user:OWNER REPOSITORY in:name fork:true`。空结果不直接等于仓库不存在。

工具目录可见、工具成功执行、模型正确解释结果是三个检查点。定位时先看 Tool Ledger，再看 MCP 错误码和实际查询条件。

相关代码：[MCP 服务](../trpc_service/mcp/service.py)、[固定地址传输](../trpc_service/mcp/transport.py)。SDK 适配使用了受保护接口，所以当前精确固定 tRPC 版本，升级时需要重验该边界。

## Tool、Skill 与审批

内置通用工具包括 `calculate`、`current_time`、`http.get`、`workspace.list`、`workspace.read`、`knowledge.list`、`knowledge.search`。HTTP 工具限制为 Agent 获准的 HTTPS 公网主机；知识写操作不暴露给模型。

Skill 通过 `FsSkillRepository` 和 `SkillLoadTool` 加载审核过的操作说明，目前目录包含 `hr-assistant`、`code-review`，不注册命令执行工具。Skill 加载本身没有外部写副作用，不按远端写工具执行。

需确认的能力创建持久 Approval 并结束当前轮次，不占用 Worker 一直等待用户。用户在原会话回复确认短码后，系统校验租户、Agent、身份、会话和配置版本。工具调用先写 Ledger；成功结果可重放，UNKNOWN 不允许盲目再执行。

## 用量与观测

模型调用前预留预算，完成后按返回的实际用量结算，失败或取消走释放路径。Usage Ledger 使用请求幂等键；配置单价计算的是平台估算成本，不等于供应商最终账单。

Trace 上下文随任务持久化并在投递时恢复。Prometheus 保存低基数运行指标，Usage Ledger 保存业务用量；日志脱敏后由 Alloy 写入 Loki，Trace 进入 Tempo，Grafana 查询这些数据源。当前压测没有把 Grafana 曲线作为统计依据，性能结论来自 Locust 与数据库核对。

人员密码采用 Argon2id，浏览器认证使用服务端 Session、HttpOnly Cookie 和 CSRF 校验。IM/MCP 密钥按租户加密且查询不回显。测试结果和覆盖率的适用版本见[测试结果](测试结果.md)。
