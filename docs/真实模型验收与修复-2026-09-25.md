## 真实调用发现的缺陷

| 问题 | 修复与证据 |
| --- | --- |
| 模型思考内容进入最终回复 | SDK `Event.get_text()` 会合并 `thought=True` 的内容。适配器现在只提取公开回答；纯思考、无最终回答时判定失败。回归同时检查回复和持久化事件。 |
| 第二轮对话混成一条用户输入 | 恢复的历史回复没有 SDK 分支标识，被 RequestProcessor 当作其他 Agent 的内容，变成 `[assistant]: …` 并合并进用户消息。恢复 `branch=assistant`，通过真实 SDK 构造请求的测试确认 `user → model → user` 三条消息。 |
| 工具轮次漏计 token | 原先每个模型事件覆盖前一次用量。现在累加各次非流式最终事件用量，覆盖“模型请求工具 → 工具结果 → 模型回答”两次调用。 |
| 模型失败时日志出现 ContextVar 清理异常 | 收到 SDK 错误事件后先消费完流，在原任务中完成 SDK 清理，再抛出失败；避免在 `yield` 处提前退出而由其他任务清理 tracing 上下文。此修复针对错误事件路径，不代表改变 SDK 的全部取消行为。 |
| 更换向量模型可能混用旧索引 | Knowledge Base 记录实际配置的模型名；读写前检查模型一致性。不一致时明确要求重建，不静默使用旧向量。 |

新增 6 项回归测试，其中历史角色测试经过“移除分支修复后失败、恢复后通过”的验证。模拟模型只用于稳定复现 SDK 边界；下面真实验收使用真实云端模型。

- `qwen3.7-plus` 和业务策略所选的 `qwen-long` 均真实返回 `AllocationQuota.FreeTierOnly`（403）。这是供应商额度限制，不能将失败记为通过，也不会自动修改供应商计费设置。

## 重复运行

新增显式运行的验收脚本 [tests/live_model_check.py](../tests/live_model_check.py)，不会被普通 pytest 自动收集，也不会在常规回归中消耗云端额度。

```bash
PYTHONPATH=. .venv/bin/python tests/live_model_check.py \
  --database-url postgresql+asyncpg://trpc@127.0.0.1:55432/trpc_agent \
  --model-catalog-id '<管理台中的可用模型 UUID>' \
  --credential-id '<管理台中的模型凭据 UUID>'
```

数据库端口用 `docker compose port postgres 5432` 核对，API 端口和前缀读取当前 Settings。令牌和数据库密码默认读取 `.secrets/` 文件，不从命令行传入密钥。脚本检查 API 与数据库确为同一个实例，再创建内部渠道。

覆盖：基础问答、多轮记忆、真实计算工具、真实向量入库、检索与引用、文档替换及旧版本不可见、删除，以及同一任务重复入队与唯一用量事实。替换后读取允许使用平台自动检索注入的真实上下文；首次检索明确要求调用工具并验证 Tool Ledger。引用接受文件名或平台提供的 `[知识1]` 标记，不强迫模型采用单一自然语言表述。

测试租户、Agent、策略和渠道逻辑停用，内部待投递回复取消；保留审计、会话和用量记录用于复核。业务租户配置不由测试脚本修改。
